## Listener model

UDP 10100 is the fixed transcoder listener.

UDP 10101-10199 are dynamic codec-stream listeners created as `10100 + stream_id`; they are therefore recorded separately and not required to exist immediately after a restart. All other fixed XLXD listeners remain fail-closed release requirements.

## Live dashboard compatibility hotfix

After the core release, the public live boxes stopped recognizing active transmissions because XLXD 2.6.0 changed the `Opening stream` log format. Production now emits forms such as:

- `for CALLSIGN / DMR on GATEWAY ... with sid ...`
- `for CALLSIGN / YSF on GATEWAY ... with sid ...`
- `for CALLSIGN / PORT on GATEWAY ... with sid ...`

The dashboard parsers in `api/live.php` and `api/common.php` were updated with the `XLX026_LOG260_COMPAT_V2` compatibility parser. The hotfix preserves the legacy 2.5 `for client ...` format and the 2.6 `on`/`via` forms while keeping module, callsign, suffix and stream-id capture groups stable.

Validation on the production log matched all 30 of the 30 most recent `Opening stream` lines before publication. The fix was limited to the dashboard parser files; XLXD was not restarted and the core SHA remained unchanged.

## Rollback test evidence

Before the final release, the automatic rollback path was exercised in production when the validator incorrectly treated transient UDP 10102 as a permanent listener. The release automatically restored XLXD 2.5.3 and confirmed it active. Source review then established the dynamic 10101-10199 port model, the validator was corrected, and the final 2.6.0 release passed.
